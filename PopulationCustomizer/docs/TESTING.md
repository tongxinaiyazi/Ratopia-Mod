# 人口自定义实机验收

## 自动验证

Ratopia 完全退出后执行：

```powershell
$env:RATOPIA_DIR = '<Ratopia目录>'
dotnet test .\PopulationCustomizer.sln -c Release /p:InstallAfterBuild=false
.\scripts\Package.ps1 -RatopiaDir $env:RATOPIA_DIR
```

记录游戏程序集哈希、插件 DLL 哈希、ZIP 哈希、存档备份位置和测试结果。

## 加载与界面

1. 启动游戏并进入已有测试存档，确认日志出现插件加载、四个补丁安装信息。
2. 点击原版人口数量打开鼠民名单，确认“上限”按钮位于顶部放大镜按钮左侧且只出现一次。
3. 关闭并重复打开鼠民名单两次，确认入口仍只出现一次，不遮挡搜索、筛选或关闭按钮。
4. 点击“上限”打开面板，确认鼠民和机器鼠均显示当前数量、原版上限和生效上限。
5. 分别测试空值、负数、1000、字母和小数，确认不会应用，并显示中文错误。
6. 打开输入框输入数字时确认不会触发女王移动或其他原版快捷键；关闭或按 `Esc` 后仍停留在鼠民名单且原 Action Map 恢复。

## 上限行为

1. 分别只启用鼠民、只启用机器鼠以及同时启用两类自定义，确认互不影响。
2. 把鼠民上限设为当前数量，尝试鼠民招募，确认原版拒绝继续新增。
3. 把机器鼠上限设为当前数量，尝试机器鼠制造，确认原版拒绝继续新增。
4. 把两类上限调高，确认对应的鼠民招募和机器鼠制造恢复。
5. 把上限调到低于当前数量，确认单位不会删除，面板显示超额提示，并停止新增。
6. 点击“恢复原版”，确认人口栏和机器鼠制造重新使用原版动态上限。

## 存档、兼容与卸载

1. 在存档 A 应用一组值，正常保存、退出、重新读档两轮，确认数值稳定且不重复初始化。
2. 切换到不同存档 B，确认它仍使用自己的设置或原版默认，不继承存档 A 的值。
3. 在新建存档测试首次进入保持原版，应用后正常保存再重载。
4. 与 `RatopiaCitizenListUpdateMod` 同时启用，复验招募列表、人口按钮和招募判定。
5. 启用 Mod 保存后退出游戏，临时移除 DLL，再用原版读取并保存同一存档，确认可正常运行。
6. 重新安装 DLL，点击恢复原版并保存；再次移除 Mod，确认存档仍可读取。
7. 检查 `BepInEx\LogOutput.log`，确认没有 Harmony 失败、重复按钮、持续异常或程序集加载错误。
