# 研究与贸易优化

一个完全独立的 Ratopia（鼠托邦）BepInEx 5 Mono Mod。它保留原版研究队列、贸易协议和存档格式，在解除研究/贸易数量限制的基础上，为普通城市开放本地完整商品池，并允许安全调整正在执行的普通商品贸易。

## 功能

### 研究队列

- 普通、工程、教义研究可以继续预约，不再受原版 3 项上限限制。
- 预约研究不再要求当前持有足够研究点，也不会提前扣除研究点。每个分支只有队首项目会尝试启动；研究点达到该项目完整费用时才一次性扣除并从 0% 开始计时。
- 三个分支同时等待点数时，沿用原版处理顺序：普通研究 → 工程研究 → 教义研究。不会跳过昂贵队首去启动后面的便宜项目。
- 取消未付款预约不会返还研究点；取消已经启动的项目仍沿用原版全额退款。特殊信徒数量研究和其他即时研究保持原版规则。
- 黑色摘要框优先显示最先排入的五项；超过五项时，第六格显示不可点击的 `...`，其余项目仍按原顺序推进。
- 队列节点只增长并复用，黑框按画布左边界对齐，不改变研究存档数据。

### 贸易队列

- 贸易协议不再受原版 3 项上限限制；列表按实际数量扩展并沿用原版对象池。
- 贸易列表与国家详情统一显示 `当前数量/∞`。
- 不修改 `MaxTradeAgreementCount`，避免与“特殊鼠鼠”修改同一 getter 发生冲突。

### 普通城市完整商品池

- 完全由非全局本地资源组构成的普通城市，会开放其原始配置中全部启用的进口、出口候选商品，不再随季节随机抽取少数商品。
- 仍保留原版方向、繁荣度要求、禁用资源和正在交易同种商品的过滤规则。
- 只要城市任一方向引用原版全局公共池，整座城市就保持原版逻辑。玉光城、安德城、曼迪康塔等特殊市场城市本轮不会展开超大候选池，仍使用原版随机数量、进出口排重、跨城市全局排重、存档值与季节轮换。
- 旧存档读入时，普通城市会立即重建完整本地池；全局公共池城市会保留合法的原版当期商品。若旧版 Mod 已把超大全局候选池写入存档，则按原版 `PickCount` 上限识别并立即调用原版重抽一次，随后继续使用原版季节轮换。
- 国家详情每个方向最多三行、每行 6 项，即最多显示 18 项。当前适配数据中的普通城市单方向最多 17 项，因此可直接完整显示。
- 任一方向超过 12 项时，进口和出口统一切换为固定 6 列的 `52×52` 紧凑商品格，格间距为 2；三行内容仍装在原版方向区域内，父面板与“新增贸易”按钮保持原位，不再被推出屏幕。
- 国家详情进出口列表中，正在执行贸易协议的商品会以背景色和图标描边突出显示。有限期贸易默认颜色为 `rgb(145, 135, 106)`，无限期贸易默认颜色为 `rgb(96, 169, 23)`，均可通过 BepInEx 配置自定义：`TradeDetailSlot/ActiveTradeBackgroundColor`（有限期）与 `TradeDetailSlot/InfiniteTradeBackgroundColor`（无限期），格式 `R,G,B`，范围 0-255，非法值自动回退对应默认色。

### 调整正在执行的贸易协议

- 普通商品协议处于执行或故障状态时，详情中的“续约”位置会显示“调整”。商品方向、商品种类与仓库锁定，只能修改每日数量和期限。
- 新建、续约和调整普通商品协议时，期限 `0` 都显示并保存为原版支持的“无限期”。
- 数量沿用当前繁荣度上限。若繁荣度下降导致旧协议数量超过当前上限，可以保持旧值不变；一旦改动，就必须落在当前允许范围内。
- 编辑使用独立工作副本；取消不会改动真实协议。最终确认后，本期从当前时间重新开始，当前交易次数与成功次数清零，新数量从下一次交易起生效。
- 协议 ID、方向、商品、仓库、状态、累计交易次数和累计金额保持不变；调整免费，删除仍使用原版费用。
- 瓦特资源（4001）、贡品、电力和其他特殊协议不进入此调整流程。

### 周期市场价

- 每经过一个原版最长签约期（当前适配版本为 `Defines.DayOfQuarter = 12` 天），所有仍在执行或故障中的普通商品协议会按当时市场价更新协议价格。
- 第 0 天不触发；更新发生在原版当天市场价格计算之后，只影响后续交易，不修改已有累计历史、数量、期限、状态或当前进度。
- 手工调整协议不会立即重定价；如果编辑面板跨过价格更新日，最终确认会采用真实协议的最新价格。

## 环境与兼容性

- Ratopia Mono 版
- .NET Framework 4.7.2
- BepInEx 5.4.23.5
- Harmony 2.9.0（使用 BepInEx 自带版本）
- 适配的 `Ratopia_Data\Managed\Assembly-CSharp.dll` SHA-256：
  `C94847D858EED368D2082E9715D0C79DD79309631BEF861C6BEBD467306D6E1D`

游戏更新后若该哈希变化，请先停用本 Mod 并等待兼容性确认。插件对关键签名和 IL 结构有契约测试；补丁安装异常时会撤销本 Mod 已安装的全部 Harmony 补丁并停用。

Mod 自有文本支持简体中文、繁体中文、英语和韩语，无法识别语言时回退英语；确认、取消和无限期文本继续复用原版翻译。

## 安装与升级

1. 完全退出 Ratopia。
2. 确认游戏已安装 BepInEx 5.4.23.5。
3. 如果从 `0.1.0` 升级，先移除旧目录 `BepInEx\plugins\UnlimitedResearchAndTradeQueues`，避免同一 GUID 重复加载。
4. 解压发布包到游戏根目录，最终文件应位于：
   `BepInEx\plugins\ResearchAndTradeOptimization\ResearchAndTradeOptimization.dll`
5. 启动游戏，在 BepInEx 日志中确认“研究与贸易优化 v0.3.0 已启用”且所有补丁均安装成功。

本工程默认只构建、不自动安装：`InstallAfterBuild=false`。发布包不会携带游戏、Unity、BepInEx 或 Harmony DLL。

## 卸载

1. 完全退出 Ratopia。
2. 在仍启用本 Mod 时，先取消研究队列中所有尚未扣点、仍在等待研究点的预约并保存。
3. 删除目录 `BepInEx\plugins\ResearchAndTradeOptimization`。
4. 确认旧目录 `BepInEx\plugins\UnlimitedResearchAndTradeQueues` 也不存在，再启动游戏。

## 存档说明与风险

本 Mod 不添加配置文件、不写入自定义存档字段，也不改变原版研究/贸易数据结构。未付款研究预约使用原版 `UpgradeNode.m_StartTime` 的保留负值标记，因此旧存档中已经预付的队列会继续被识别为已付款，不会重复扣点；但原版不认识该标记，所以卸载前必须先清空所有未付款预约。城市商品池仍由原版字段保存；全局公共池城市始终使用原版保存和轮换逻辑，旧版造成的超长公共池会在首次读档时按原版逻辑重抽一次。普通城市在卸载后会继续读取最后保存的商品数组，并在后续原版轮换周期恢复原版随机行为。无限期是原版已有的 `GoalTradeCount = 0` 语义。

为稳妥起见，请先复制一份测试存档副本再验收。推荐执行两轮“保存 → 完全退出 → 重新读档”，随后在测试存档副本上移除本 Mod，确认原版仍能读档。不要把首次验收放在唯一主存档上。

## 日志与排查

日志位置：`BepInEx\LogOutput.log`。

正常启动会逐项记录补丁安装；首次创建延迟扣点研究预约、首个预约实际扣点启动、首次扩展研究节点、首次显示超过 7 个贸易槽位、首次生成完整商品池、旧存档超长公共池修复和首次季度价格更新也会记录诊断信息。若看到“补丁安装失败”或“本 Mod 已停用”，请停止用主存档测试，并附上完整日志与当前 `Assembly-CSharp.dll` 哈希。

游戏内验收步骤见源码包中的 `docs\TESTING.md`。
