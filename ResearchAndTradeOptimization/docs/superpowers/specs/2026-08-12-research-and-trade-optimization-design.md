# 研究与贸易优化 v0.2.0 设计

## 目标

将现有“贸易站和研究去除最大队列限制”升级并更名为“研究与贸易优化”。保留已经验收的无限研究队列、五项研究摘要与无限贸易协议功能，同时开放每座城市配置的完整普通货物贸易池，允许修改未结束协议的数量和期限，并让未结束协议按全局季度周期自动使用当时市场价。

本 Mod 继续适配 SHA-256 为 `C94847D858EED368D2082E9715D0C79DD79309631BEF861C6BEBD467306D6E1D` 的 `Assembly-CSharp.dll`、BepInEx 5.4.23.5、Harmony 2.9.0 和 .NET Framework 4.7.2。

## 已锁定的玩法行为

### 现有功能

- 研究预约实际上限保持为 `int.MaxValue`。
- “研究中”黑色摘要框按原始队列顺序显示最先预约的五项；超过五项时，第六格只显示 `...`。
- 普通贸易协议数量不设人为上限，贸易列表继续动态扩展并显示 `当前/∞`。
- 不修改 `MaxTradeAgreementCount` getter，保留与“特殊鼠鼠”等 Mod 的兼容性。

### 城市完整商品池

- 每座城市开放其原始配置中全部进口和出口普通货物，不再按 `PickCount` 随机抽取。
- 进口与出口分别按对应原始配置构建，不交换方向；资源组及组内顺序保持稳定。
- 同一方向重复出现的资源只保留一次，并采用第一次出现时的繁荣度要求。
- 保留原版禁用资源过滤、城市繁荣度门槛和“已有未结束同资源协议时不重复列出”的规则。
- 不采用原版为随机抽取服务的跨城市全局占用池；一个资源只要属于该城市的原始池，就可在该城市出现。
- 已有存档读入后立即重建完整池；新游戏初始化及以后每次原版轮换也生成同一个完整池，因此季节更替不会改变可贸易商品。

### 修改现有协议

- 仅支持普通货物协议。电力资源 `TileType 4001`、贡品与其他特殊协议保持原版。
- 原版判定为未结束的协议可调整：`Run` 和故障状态 10–17。
- `End` 和 `Stop` 仍按原版“已结束”处理，只能续约，不进入调整流程。
- 协议详情中的原版“续约”槽动态复用：未结束普通货物显示“调整”，已结束协议仍显示“续约”。
- 调整窗口沿用原版贸易单；方向、商品和仓库可见但锁定，只允许操作数量、期限和确认。
- 数量保持原版当前繁荣度上限。若已有数量因繁荣度下降而高于当前上限，在用户未改数量时允许原值通过；只要用户修改数量，新值必须落入当前原版范围。
- 有限期限保持原版范围；`0` 直接使用原版 `IsInfinitePeriod()`，界面显示原版“无限期”。
- 调整免费，不扣货币、不降低关系；删除/废除协议继续使用原版代价。
- 确认调整后，期限从当前时间重新计算，当前贸易周期数和成功周期数清零；新数量从下一次实际贸易生效。
- 商品、进出口方向、仓库、协议 ID、历史累计贸易次数、历史累计金额及进入调整时的运行/故障状态保持不变。
- 取消或退出调整时，原协议的任何字段都不得变化。

### 全局季度自动调价

- 自动调价周期使用原版最长普通贸易期限，即 `Defines.DayOfQuarter` 个游戏日。
- 采用无额外存档状态的全局日历边界：当 `TotalDays > 0` 且 `TotalDays % Defines.DayOfQuarter == 0` 时更新。
- 在当日原版城市市场价格计算完成后，遍历所有城市及其未结束普通货物协议，把协议价设为该城市该资源的 `DiplomaticCountryResourceData.NowValue`。
- `Run` 和故障状态 10–17 都会更新；断货、缺仓库、低关系、断路等暂停不会冻结日历周期。
- `End`、`Stop`、电力、贡品和特殊协议不更新。
- 新价格只影响此后的交易；历史累计金额不追溯重算。
- 手动调整数量或期限不会触发即时重定价，而是保留该协议当时正在使用的协议价。
- 若调整窗口跨过季度边界，确认时从真实原协议复制最新协议价，避免用较旧的工作副本回滚自动调价。
- 世界第 0 天不触发；相同边界日重复调用只会写入相同市场价，行为幂等。

## 技术设计

### 完整商品池适配器

用 Harmony Prefix 接管 `DiplomaticCountryData.PickUpTradeResources(DiplomaticAsset, DiplomaticCountryTradeRawData[], ref KeyValuePair<int, TileType>[])`。纯逻辑构建器展开传入方向的所有资源组，过滤禁用/忽略资源并稳定去重，生成“繁荣度要求 → 资源”数组和对应资源数组，然后跳过原版随机实现。

原版 `SetTradeResource()` 继续负责清空列表、分别调用进口/出口建池及运行 `RefreshResource()`。`DiplomaticCountryData.SetSavableData()` 的 Postfix 再调用一次完整建池，使旧存档内已保存的随机数组立即被当前城市配置替换。运行时异常记录后允许原版方法执行，避免留下半初始化列表。

### 协议调整会话

增加一个只存在于外交 UI 生命周期内的调整会话，保存：原协议引用、独立工作副本、进入时的状态、进入时的数量，以及当前是否正在处理数量/期限控件。关闭贸易单、确认完成、外交 UI 清理或异常时都清除会话。

`DiplomaticTradeDetailUI.Refresh()` 的 Postfix 修改第二个操作槽的标题和 `TypeTradeOrder`。`DiplomaticUI.OnTradeDetailEvent()` 的 Prefix 只接管 `Modify`，打开类别为 `Trade` 的原版贸易单并传入工作副本。

调整模式下：

- `DiplomaticTradeSheetLayoutUI.SetData()` 的 Postfix 只让 `Count`、`Period` 和 `Confirm` 行进入焦点与提交路径。
- `DiplomaticTradeSheetDetailUI.SetData()` 的 Prefix 只对 `Count`、`Period` 强制启用原版左右调节控件。
- `DiplomaticTradeSheetUI.OnSubmitedEvent()` 的 Prefix 只替换会话工作副本，不调用原版 `CountryData.ReplaceSheet()`，防止编辑途中污染真实协议。
- 最终确认先做字段白名单校验，再显示本 Mod 的本地化二次确认。确认后调用 `AgreementTradeSheet(当前时间)`，恢复进入时的状态和真实协议当前价格，最后通过原版 `ReplaceSheet()` 原子替换。
- 任意校验失败或异常都保留真实协议并关闭/清理会话，不向游戏主循环传播异常。

### 自动调价运行时

在 `DiplomaticCountryPackage.RunProcessDaily(TimeSpan, DiplomaticAsset)` 安装 Postfix。原版方法已经先运行每个城市的 `DiplomaticCountryResourceData.RunProcess()`，因此 Postfix 读取到的是该日最新市场价。

纯逻辑规则负责判断季度边界、普通货物类型和允许状态；Unity/Harmony 适配层只枚举 `CountryArray`/`Sheets`、读取资源数据并调用 `SetTradeValue()`。`Defines.DayOfQuarter <= 0`、城市/资源数据为空或单项更新异常时跳过并记录，其他协议继续处理。

### 本地化

新增“调整”、调整说明和最终确认提示的简体中文、繁体中文、英文及韩文文本。通过 `I2.Loc.LocalizationManager.CurrentLanguageCode` 选择，未知语言回退英文。原版已有的“无限期”、确认和取消文本继续复用游戏翻译。

## 存档、升级与卸载

- 不增加配置文件或 Mod 专用存档字段。
- 完整商品池继续写入原版进口/出口数组；协议数量、期限、价格和累计统计继续写入原版协议字段。
- 重复初始化和重复读档必须幂等，不复制资源或协议。
- 移除 Mod 后，原版能读取最近保存的测试存档：完整商品池会保留到下一次原版随机轮换；协议保留最后一次自动更新的价格，此后不再自动更新。
- 插件显示名改为“研究与贸易优化”，版本改为 `0.2.0`；GUID 保持 `cn.ratopia.unlimitedresearchandtradequeues`。
- 源码目录、解决方案、程序集、DLL、命名空间和安装目录统一迁移为 `ResearchAndTradeOptimization`。
- 安装前确认游戏退出，完整备份 `Ratopia_Data\SaveFile` 和旧 DLL并校验哈希；新 DLL 安装校验成功后移走旧安装目录，禁止两个程序集同时加载。
- 发布包为 `研究与贸易优化-v0.2.0-BepInEx5.zip`，只包含 `BepInEx/plugins/ResearchAndTradeOptimization/ResearchAndTradeOptimization.dll` 与根目录 README。
