# 贸易方向与无限期修复设计

## 问题证据

- 当前 Mod 分别展开 `CountryToHometownArray` 与 `HometownToCountryArray`，但没有保留原版 `_useResources` 的跨方向排重语义。
- 曼迪康塔、Granbazaar、Untermarkt 的进口和出口原始配置都引用全局 `Exception_A` 商品组。当前实现因而把同一完整列表复制到两个方向。
- 原版普通贸易 `Period` 控件在 `SetData` 中把 `_minValue` 设为 `1`。当前 Mod 仅在已有协议调整会话中改为 `0`，所以新建和续约入口无法选择无限期。
- 原版数据层已经把 `GoalTradeCount == 0` 定义为无限期，并有现成的本地化显示与存档字段，不需要自定义存档格式。

## 修复方案

### 完整商品池

由一次 `SetTradeResource` 前缀联合生成两个方向，替代对私有 `PickUpTradeResources` 的两次孤立拦截。

1. 将国家两个方向的全部原始条目视为一组有序分配桶；每个桶保留方向、繁荣等级、资源组和原版 `PickCount` 权重。
2. 资源组只被一个方向引用时，该组的完整资源保留在该方向。
3. 同一资源组被两个方向共同引用时，按各桶的 `PickCount` 权重稳定分配完整资源；同一商品最多进入一个桶。
4. 同一商品跨不同组重复时继续全国家排重；优先保留更低繁荣等级，然后按原始方向/条目顺序稳定决胜。
5. 忽略列表继续生效。运行中的协议仍由原版 `UsedTradeResource` 从可新签列表临时隐藏，不改变协议本身。
6. 读档和季节刷新都调用同一联合生成入口，保证结果幂等且不再随机变化。

### 无限期

- 普通 `TypeTradeSheet.Period` 的最小值统一改为 `0`，覆盖新建、续约和调整已有普通商品协议。
- `TypeTradeSheet.SpecialPeriod` 不修改，瓦特及特殊协议沿用原版。
- 期限为 `0` 时继续由原版显示“无限期”、写入 `GoalCount = 0`，并由原版 `IsInfinitePeriod()` 保持协议不因次数结束。

### 国家详情商品预览

- 国家详情没有滚动区域，不能直接承载完整大商品池。进口与出口各最多展示 12 个图标（两行）。
- 超过 12 项时，在对应方向标题后显示 `... (+N)`，说明还有 N 项未在摘要中展开。
- 限制只作用于 `DiplomaticWorldDetailResourceLayoutUI.SetData` 的预览参数，不修改国家商品数组；进入贸易界面仍可选择该方向的全部商品。

## 可靠性与测试

- 纯逻辑测试覆盖共享组按权重分割、两方向不相交、全部资源恰好出现一次、繁荣等级与稳定顺序、普通独立组不串方向以及忽略项。
- 预览测试覆盖 0、12、13 和大商品池，确保最多显示 12 项并准确计算隐藏数量。
- 合同测试确认联合补丁目标为 `DiplomaticCountryData.SetTradeResource`，原版 `Period` 的下限仍为 1、无限期数据语义仍为 0。
- 运行时异常回退到原版完整方法，不留下半更新数组。
- 不新增配置或自定义存档字段；安装前继续要求 Ratopia 已退出并备份现有 DLL。
