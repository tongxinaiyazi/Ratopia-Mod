# 游戏内验收清单

所有验收都应在测试存档副本上进行。开始前完全退出游戏，安装经 Release 测试和发布包内容验证的 DLL，再启动 Ratopia。

## 启动与日志

- [ ] `BepInEx\LogOutput.log` 中出现插件名称“研究与贸易优化”和版本 `0.3.0`。
- [ ] 全部补丁逐项安装成功，无 IL 结构不匹配、Harmony 异常或插件停用记录。

## 研究队列

- [ ] 将研究点消耗到 0，普通研究、工程研究、教义研究仍能分别预约至少 5 项，预约期间研究点保持 0。
- [ ] 让三个分支的队首费用均高于当前点数，经过一段游戏时间后三个队首都保持 0%，没有偷偷推进。
- [ ] 逐步增加研究点：达到完整费用时对应队首只扣一次点数并从 0% 开始；费用不足时不部分扣点，不跳过队首。
- [ ] 三个分支同时等待且点数只够一个时，确认启动顺序为普通研究 → 工程研究 → 教义研究。
- [ ] 分别取消未付款预约和已启动项目：前者不增加研究点，后者按原版返还；再取消带依赖的预约，确认逐项判断且没有重复退款。
- [ ] 特殊信徒数量研究仍要求原版条件，并保持原版即时完成行为。
- [ ] 普通研究、工程研究、教义研究分别预约超过 3 项，队列数据仍按原顺序推进。
- [ ] 至少一个研究类别达到 8 项，摘要从左到右显示最先预约的 1–5 项，第六格显示 `...`，编号 6–8 不显示。
- [ ] 黑色摘要框左边界与画布左边界对齐，第一张卡片和编号完整可见；省略号位于第五项右侧且不可点击。
- [ ] 完成或取消第一项后，原编号 2–6 成为新的可见前五项，顺序没有丢失或重复。

## 贸易队列与商品池

- [ ] 同时建立至少 8 个普通商品协议；列表显示全部协议，列表和国家详情均显示 `当前/∞`。
- [ ] 与“特殊鼠鼠”同时启用时，双方日志无补丁冲突，贸易仍可超过 3 项。
- [ ] 分别查看多个普通城市的进口和出口，确认其本地配置候选商品全部列出，较高繁荣度商品仍保留原版锁定表现。
- [ ] 至少选择一个单方向有 13–17 项的普通城市；任一方向进入第三行时，进口和出口统一使用固定 6 列、`52×52` 的紧凑商品格，最多三行完整显示。
- [ ] 检查索尔德姆等两个方向均超过 12 项的城市：“新增贸易”按钮保持原位、完整处于屏幕内，并且鼠标和键盘都可以触发。
- [ ] 连续切换只有一行、两行和三行商品的城市，确认标准网格和紧凑网格能相互恢复，不累计缩放或漂移。
- [ ] 对第三行商品逐项检查悬浮说明和点击，确认缩小图标没有破坏交互区域。
- [ ] 普通城市跨季节或到达原版商品轮换日后仍保持完整；保存读档后无需等待换季也立即重建完整本地池。
- [ ] 已经执行中的同种商品仍按原版规则从新协议可选列表中隐藏。
- [ ] 检查玉光城、安德城、曼迪康塔等全局公共池城市：每个方向仍为原版当期约 8–10 项，没有被展开成上百项；进口与出口不混用或重复。
- [ ] 首次读取曾出现 70/49 等超长公共池的旧测试存档时，日志出现“已修复旧存档中的超长全局贸易商品池”，上述三座城市立即恢复原版数量；普通城市不出现该修复日志。
- [ ] 保存并读档后，上述全局公共池城市保留存档中的当期原版商品；跨过原版轮换日后仍按原版重新随机抽取。
- [ ] 当前普通城市单方向最多 17 项，均不应出现隐藏数量标题、图标截断或覆盖“贸易”按钮。

## 调整、无限期与价格

- [ ] 执行中和故障状态的普通商品协议显示“调整”；结束协议仍显示原版“续约”。瓦特、贡品、电力和特殊协议不显示错误的调整入口。
- [ ] 调整面板只能操作数量、期限和确认；商品、方向、仓库不可点击。
- [ ] 修改数量后确认，下一次交易采用新数量；取消编辑后数量、期限、价格和进度完全不变。
- [ ] 将期限设为 `0`，界面显示原版“无限期”，并且协议不会因完成目标次数而结束。
- [ ] 分别从新建协议、续约协议和调整执行中协议进入期限选择，确认三处都能选到“无限期”。
- [ ] 繁荣下降后，原有超限数量保持不变时可确认；改成新的超限数量会被阻止并显示提示。
- [ ] 确认调整后，本期进度从现在重新计算，当前/成功次数清零；协议 ID、原状态和累计次数/金额保持不变。
- [ ] 到达第 12、24、36……天的每日更新后，活动普通协议价格更新为当天市场价；第 0 天不触发，历史累计不变。
- [ ] 在跨过价格更新日时保持调整面板打开，再确认，最终价格使用真实协议刚更新的市场价。

## 保存、读档与卸载

- [ ] 同时保留未付款和已付款研究后保存、完全退出并读档，核对点数、付款状态、0% 等待、研究顺序、城市商品池、协议数量、期限、价格、状态和进度；旧版本已预付队列不应再次扣点。
- [ ] 再重复一轮“保存 → 退出 → 读档”，结果仍一致。
- [ ] 先在启用本 Mod 时取消所有未付款研究预约并保存，再完全退出游戏、移除本 Mod，由原版读取同一个测试存档副本。
- [ ] 确认原版可读档；超过原版界面上限的内容如何显示，以原版自身行为为准。

出现异常时立即停止使用主存档，并保留完整 `BepInEx\LogOutput.log`、游戏版本和 `Assembly-CSharp.dll` SHA-256。
