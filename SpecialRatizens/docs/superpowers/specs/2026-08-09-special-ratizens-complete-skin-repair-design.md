# 特殊鼠鼠皮肤完整修复设计

## 背景与已确认根因

当前游戏为 Ratopia 1.0.0600、BepInEx 5.4.23.5，已安装 `特殊鼠鼠 v0.1.1`。

新建世界 `鼠托邦_W02` 的手动存档包含三名市民。离线反序列化结果如下：

- 普通市民“林”为 Male，`Skin`、`Face`、`Hair`、`Dress` 均存在。
- 特殊市民“大正”和“皮卡丘”实际均为 Female，保存的皮肤字典为空。

日志表明两名特殊市民均被识别并执行了自定义皮肤注册，没有材质、纹理、Shader 或 Spine 资源异常。原版程序集 IL 进一步证明：

1. `SpineDresserElement.AssembleData` 使用 `Sp_SkinInfo.m_Gender.ToString()` 精确选择模板。
2. 找不到对应性别模板时，该方法直接返回，不写入任何皮肤部件。
3. 当前模组的 `RegisterCustomSkin` 却固定使用特殊鼠鼠 CSV 中的 `UnitGender` 创建唯一模板。
4. `UpdateUnitCustomSkin` 会先调用 `ClearSkins`，再尝试组合；性别不匹配时便留下空字典。

因此，问题不是资源缺失，也不是普通鼠民再次被误处理，而是“角色实际性别、皮肤对象性别与特殊模板性别不一致”叠加“先清空、后尝试”的破坏性更新顺序。

## 目标

1. 特殊鼠鼠无论实际性别是否与 CSV 预设相同，都能显示完整身体、脸、头发和衣服。
2. 保留角色的实际游戏性别，不为了适配外观而改动繁殖、称谓或其他游戏逻辑。
3. 自动修复现有存档中皮肤字典为空的特殊鼠鼠；普通市民完全不进入该修复流程。
4. 自定义皮肤组合失败时，不再留下空皮肤：优先恢复原外观；原外观也不完整时回退为原版默认市民外观。
5. 保持 BepInEx 5 Mono 兼容，并发布为 `v0.1.2` 独立模组包。
6. 构建、离线测试、打包和安装后不自动启动游戏，由用户进行运行时验收。

## 方案比较

### 方案 A：以实际性别为准并采用事务式重建（采用）

注册模板时读取当前 `Sp_SkinInfo.m_Gender`；市民加载后先使皮肤对象性别与 `T_Citizen.m_Gender` 一致。重建前保存原皮肤，确认目标模板存在后再清空；重建结果不完整则回滚或使用原版默认皮肤。

优点是不会改变角色游戏性别，能修复新旧存档，并消除“组合失败后彻底隐身”的风险。缺点是实现与测试比单行改动稍多。

### 方案 B：强制角色性别等于 CSV 预设（不采用）

在加载和生成后把 `T_Citizen.m_Gender` 改成 `CustomSpecialUnit.gender`。

这能让现有模板匹配，但会改变已经生成角色的游戏性别，可能影响繁殖和其他系统，不符合最小侵入原则。

### 方案 C：同时注册 Male/Female 两套模板（不采用）

为每个特殊鼠鼠复制两套模板。

这能绕过部分不匹配，但不能保证皮肤对象性别与角色性别一致，而且默认头发、服装回退可能选错性别；同时也没有解决“先清空、失败即为空”的根本风险。

## 修复设计

### 1. 性别来源

- 特殊候选人生成时，继续用 CSV `UnitGender` 作为初始性别设定。
- 实际套用外观时，以当前角色的真实 `T_Citizen.m_Gender` 为权威。
- `AddSpecialCitizen` 在注册皮肤前把 `citizen.m_SkinInfo.m_Gender` 同步为 `citizen.m_Gender`，但绝不反向修改 `citizen.m_Gender`。
- `RegisterCustomSkin` 使用 `skinInfo.m_Gender.ToString()` 创建 Spine 模板，不再使用 `unit.UnitGender` 作为模板选择键。
- CSV 性别值在解析入口执行 `Trim()`，预检仍只允许 `Male` 或 `Female`，避免格式空白造成隐性分歧。

### 2. 事务式皮肤重建

特殊皮肤更新按以下顺序执行：

1. 复制当前 `SkinDic` 和 `OverrideSkinDic` 作为快照。
2. 根据当前 `skinInfo.m_Gender` 验证特殊模板及对应性别的 Pairs 已存在。
3. 验证通过后才清空旧普通皮肤，并执行 `AssembleData`、`SkinSet`、`UpdateCombinedSkin`。
4. 检查结果至少包含非空的 `Skin`、`Face`、`Hair` 和 `Dress`。
5. 若检查失败，恢复完整快照并重新渲染。
6. 若快照本身也缺少上述关键部件，则按当前实际性别组装原版默认市民皮肤，保证至少能看到完整人物；此时记录一次明确错误日志，但不中断游戏。

空值允许保留在非必需部位，例如 `Bread`、`Glasses`、`Hat`、`Makeup` 和 `Cheek`。

### 3. 新建、读档与换装路径

- 新特殊市民：候选信息创建时使用候选皮肤对象的实际性别注册模板；市民实体创建完成后再次校正性别并安全重建。
- 现有特殊市民：`LoadCitizenDatas` 仍通过 `AddSpecialCitizen` 识别特殊姓名；新版逻辑会自动重建 W02 中当前为空的皮肤字典。不会直接改写存档文件，只有用户之后正常保存时才持久化修复结果。
- 工作服/换装：特殊市民每次更新服装前重新以当前皮肤对象性别生成模板，并走相同的事务式更新。普通市民继续使用原版流程。
- 会话切换：继续清理 `SpecialCitizens`、`SpecialCitizenSkins` 和候选状态，防止跨世界状态泄漏。

### 4. 日志与故障隔离

每次特殊皮肤注册只记录一条精简诊断，包含特殊鼠鼠名称、角色性别、皮肤对象性别、目标模板性别和关键部件数量。

发生异常时记录：

- 模板不存在或性别不匹配；
- 组合后缺失的关键部件；
- 使用了快照回滚还是原版默认外观回退。

异常只隔离当前特殊鼠鼠，不影响普通市民、其他特殊鼠鼠或整个读档流程。

## 测试设计

### 自动测试

1. 新增程序集契约测试，确认 `RegisterCustomSkin` 从 `Sp_SkinInfo.m_Gender` 取模板性别，而不是读取 `CustomSpecialUnit.UnitGender`。
2. 新增契约测试，确认 `AddSpecialCitizen` 在注册前将皮肤对象性别同步到角色实际性别，且不写入 `T_Citizen.m_Gender`。
3. 为关键皮肤字典完整性判定、快照回滚选择和默认回退选择增加纯逻辑单元测试。
4. 增加 CSV 性别空白归一化测试，以及所有发行数据只能得到 `Male`/`Female` 的回归测试。
5. 保留 v0.1.1 的普通市民隔离、会话清理和 `UpdateCombinedSkin` 顺序测试。
6. 对 Ratopia 当前 `Assembly-CSharp.dll` 执行 Harmony 目标和 Spine API 合同测试。

### 离线发布验证

- Release 构建和全部自动测试通过。
- 包内只包含 BepInEx 5 所需 DLL、数据、图标和说明文件。
- 校验 DLL 版本为 `0.1.2.0`，记录 SHA-256。
- 安装前确认 Ratopia 已关闭，并备份当前插件目录和实际存档根目录。
- 安装后逐文件比较发布包与游戏目录，不启动游戏。

### 用户运行时验收

1. 加载当前 W02，确认“大正”和“皮卡丘”均出现完整人物，而普通“林”保持原外观。
2. 新建世界或刷新特殊候选，确认 Male/Female 实际性别均不会导致身体消失。
3. 让特殊鼠鼠经历工作服切换，再返回标题界面并二次读档。
4. 检查日志中没有皮肤回滚、默认回退、Harmony 异常或资源错误。
5. 验收通过后再正常保存；若有问题，退出且不要保存，并提供最新日志。

离线测试只能证明补丁目标、数据和安全不变量正确；最终的 Spine 渲染结果必须由用户在游戏中确认。

## 安全与回滚

- 不自动启动游戏，不自动读写或重打包任何存档。
- 安装前必须确认 `Ratopia.exe` 未运行。
- 备份 `E:\steam\steamapps\common\Ratopia\BepInEx\plugins\SpecialRatizens`。
- 备份实际存档根目录 `E:\steam\steamapps\common\Ratopia\Ratopia_Data\SaveFile`，并校验文件集合与 SHA-256。
- 若运行时仍有异常，可在游戏关闭后恢复旧插件；存档备份保持可单独恢复。

## 验收标准

- 自动测试全部通过，且新增测试在旧实现上先失败、在新实现上通过。
- W02 的两个特殊鼠鼠会在加载时进入安全重建路径，普通市民不进入。
- 任何特殊皮肤组合失败都不能留下缺少 `Skin`、`Face`、`Hair` 或 `Dress` 的空外观。
- DLL、发布包和安装目录内容一致并可追溯到 `v0.1.2`。
- 游戏内两轮读档、换装和新建世界验收均无“只有衣服没有人物”。
