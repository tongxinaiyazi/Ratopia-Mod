# 特殊鼠鼠普通市民外观损坏存档回滚设计

## 背景与证据

鼠托邦 1.0.0600 在 2026-08-09 18:29 的启动中正确加载了 `特殊鼠鼠 v0.1.1`。本次读档使用的是 `鼠托邦_107.zip`，该存档生成于 v0.1.0 运行期间。

游戏程序集表明，保存时 `Citizen_Data` 会复制每名市民 `Sp_SkinInfo.SkinDic`，读档时再从 `Citizen_Data._skinDic` 恢复外观。v0.1.0 曾对普通市民执行 `ClearSkins` 和自定义外观组装，因而把不完整的皮肤字典写入存档。

离线反序列化对比结果：

- `鼠托邦_103.zip`（2026-08-08 23:09:39）：99/99 名市民都具有非空的 `Skin`、`Face`、`Hair` 和 `Dress`。
- `鼠托邦_107.zip`（2026-08-09 17:58:32）：102/102 名市民都缺少 `Skin`、`Face`、`Hair`，但 102/102 都保留 `Dress`。

该数据差异与游戏内“只有衣服、没有人物”的表现完全一致。`鼠托邦_103.zip` 是目前已验证的最后一个干净恢复点。

## 目标

1. 保留当前全部新旧存档，不删除、不覆盖任何存档文件。
2. 为当前真实存档目录创建新的完整离线备份，并逐文件校验。
3. 验证 `鼠托邦_103.zip` 的 ZIP 完整性、文件哈希和皮肤字典不变量。
4. 保留已安装的 `特殊鼠鼠 v0.1.1`；该版本不会再让普通市民进入自定义皮肤流程。
5. 不自动启动游戏，由用户在读档界面手动选择 `鼠托邦_103` 验收。

## 非目标

- 不直接反序列化、修改或重新打包任何游戏存档。
- 不覆盖 `鼠托邦.zip`、`鼠托邦_107.zip` 或其他较新存档。
- 不删除其他模组，不修改其他模组配置。
- 不在本次回滚中新增 v0.1.2；现有 v0.1.1 的普通市民隔离逻辑保持不变。
- 不自动保存游戏。

## 执行流程

### 1. 安全门禁

- 确认 `Ratopia.exe` 未运行。
- 确认游戏目录仍为 `E:\steam\steamapps\common\Ratopia`。
- 确认实际存档根目录仍为 `E:\steam\steamapps\common\Ratopia\Ratopia_Data\SaveFile`。
- 确认安装的 `SpecialRatizens.dll` 文件版本为 `0.1.1.0`。

### 2. 当前状态备份

在项目的 `backups` 目录创建带时间戳的 `pre-save-rollback-*` 目录，将整个真实 `SaveFile` 树复制到其中。备份完成后比较源目录与备份目录的：

- 相对文件名集合；
- 文件数量；
- 每个文件的 SHA-256。

任一差异都会中止后续操作。

### 3. 恢复点验证

对原地保留的 `鼠托邦_103.zip` 执行：

- 7-Zip 完整性测试；
- SHA-256 记录；
- 包内 `.dat`、`.json`、`.png` 三个成员检查；
- 只读反序列化检查，确认 99/99 市民均具有非空的 `Skin`、`Face`、`Hair`、`Dress`。

验证过程仅读取恢复点，不重新写入 ZIP。

### 4. 用户手动回滚

不改变游戏目录中的存档文件。用户启动游戏后，在读档界面选择世界 `鼠托邦_W00` 下的自动存档 `鼠托邦_103`。

首次进入后不要立即保存，先检查普通市民的身体、脸、头发和衣服是否全部显示。再检查工作服切换、返回标题界面后第二次读档。两轮正常后，另存为新的手动存档；不要覆盖 104–107 等较新存档，直到确认不再需要撤销。

## 失败与撤销

- 如果 `鼠托邦_103` 仍显示异常，退出游戏且不要保存，提供新的 `Player.log` 和 `BepInEx/LogOutput.log`。
- 如果需要返回较新进度，直接在读档界面重新选择 `鼠托邦_107`；由于本方案不覆盖任何存档，无需文件级恢复。
- 如果存档目录在人工验收前发生意外变化，可使用本次新建的完整备份恢复，但任何恢复覆盖都必须在游戏关闭后另行确认。

## 验收标准

- 当前完整存档备份与源目录逐文件 SHA-256 一致。
- `鼠托邦_103.zip` 通过 ZIP 完整性测试。
- 离线检查确认 99/99 名市民的 `Skin`、`Face`、`Hair`、`Dress` 非空。
- `特殊鼠鼠 v0.1.1` 保持安装，且游戏进程在离线工作结束时未运行。
- 游戏内两轮读档后，普通市民不再出现“只有衣服、没有人物”。最后一项只能由人工验收确认。
